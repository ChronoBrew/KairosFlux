## 结论（数据量=100000 档）

写路径瓶颈：standalone 模式每条写 = 1 次 WAL fsync（group commit 因 reqCh 无缓冲实际批次=1），
吞吐被磁盘 fsync 速率钉住（见 02-resource-footprint 与 03-adversarial 的同一现象）。

## 测量修正记录（校准教训，先于结论阅读）

- **现象**：修复前 smoke 报告显示 server v2 写路径 QPS 5600–15508、p50 66µs，远超本机 fsync 地板（约 250–530 次/s；v2 每次写 2 次 WAL append），且与 WAL 时间线（v2 期间 WAL 以 ~530 写/s 增长）矛盾，曾一度疑似 ack 早于 fsync。
- **根因（已实证）**：bench harness 的 genPayload 独立随机生成 OHLC 四价，约 91% 违反 quote 契约（OHLC 一致性 / 非正价格），被服务端网络路径 schema filter 以 opcode=0x81 reason="quote: OHLC inconsistent" 拒绝；被拒请求按瞬时往返计入了 QPS/延迟统计而错误数未上报——**是 harness 测量假象，不是引擎缺陷**。
- **实证链**：① WAL 时间线 v2 期间增长速率 = fsync-bound 诚实速率（~178KB/s ≈ ack 率 486 w/s × 2 append/写 × ~183B）；② kill -9 复验恢复数 ≥ 已 ack 数（无丢失，见 03-adversarial 维度 1）；③ instrumented harness 抓出 first error reason="OHLC inconsistent"；④ 修复后矩阵物理自洽（v1≈2×v2、全行 0 错误）。
- **修复**：genPayload 改乘性构造（open/close ∈ (1,101]，low = min·(0.5,1]，high = max·[1,2)，volume ≥ 0），quote 契约全约束满足；putVersioned 错误信息带 reason；写路径行新增错误列（行尾）。
- **发布口径**：修复前的 server 路径数字全部作废，以本报告为准。ack-after-fsync 契约（wal.Append 返回 = 已 fsync）在代码审查与 kill 复验中均未破坏。

报告生成耗时 30m50s。

## 已知测量缺陷（转 M5-C，不阻塞发布）

1. **100w 档读路径 SCAN/LIST_WRITES 未能测——引擎读路径文件句柄耗尽（引擎侧问题，非测量工具）**：
   - 现象：读路径 GET_AS_OF 两行完成（各 50000 采样）后，扫描阶段持续报 `scan: skip unreadable sstable ... open: too many open files`，scan 跳过全部 sstable（结果不可用），6 分钟内刷出 543 万条告警、1.9GB 日志，已 kill 止损。
   - 排除 OS 限制：进程与后台 shell `ulimit -n` 均 1048576（unlimited hard）——EMFILE 与 shell 上限无关。
   - 指向：引擎读路径在 2963 张 sstable（100w 档）规模下文件句柄累积/未回收；10w 档（约 300 张表）同路径正常（01a 完整行）。
   - 处置：转 M5-C 定位（读路径句柄生命周期）。发布口径：100w 档读路径以 GET_AS_OF 为准；SCAN/LIST_WRITES 以 10w 档（01a）为准。
2. **harness 共享 rand.Rand 并发竞态崩溃（已修复，存档）**：首轮 100w 运行在 v1 PUT 测量处 panic（`index out of range [-1]`，math/rand rngSource 内部下标被并发破坏），报告截断。已修：runSamples/runSamplesErr 向 op 传 worker 下标，各 worker 持 `rand.New(rand.NewSource(42+w))` 独立确定性流（commit 4d2789b）。本报告为修复后重跑结果（v1 行 931 QPS 正常落盘即为修复生效的证据）。
3. **LIST_WRITES 帧长上限**：服务端无界全扫在 100w+ 档超过 16MiB 帧长上限被拒绝（opcode=0x81 result_too_large），harness 如实上报"被拒绝"而非伪造延迟；有界窗口为服务端路径的正式测量口径（10w 档 p50 2.664s，锚定最后一次版本化写）。
4. 分位数随机器负载波动：同机重跑以报告为准（载入吞吐 871 w/s 与首轮 903 w/s 的差异即负载波动；本报告载入期间无其他压测进程运行）。
