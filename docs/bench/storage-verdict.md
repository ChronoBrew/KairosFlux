## 数字回顾（100w 档）
- 载入 871 w/s（单写者 fsync 界，物理自洽）；写路径 v1 931 QPS ≈ 2×v2
  452–474（v1 不建时态版本，符合预期），全 0 错误；

  "已知测量缺陷"1——**引擎侧句柄生命周期 bug，非测量工具**）。

## 裁决

1. **SSTable 按类型分区：不做（定档）**。100w 量级下写路径与点读路径均无
   超线性恶化证据；扫描失败是句柄泄漏类 bug，分区解决不了句柄生命周期。
   诚实定档："当前存储形态在 100w 量级无需分区"——触发重审的条件：
   数据量跨入 500w+ 或出现压实写放大导致的写入退化曲线。
2. **句柄生命周期修复：必做（新任务 #52）**。读路径扫描须在扫描结束/出错
   路径上关闭句柄；修复后重测 100w 档 SCAN/LIST_WRITES 补全 01.md 空缺格。
   这是本次压测抓到的唯一引擎级存储缺陷，优先于一切"优化"。
3. **内存面**：MemoryMax=2G+GOGC=60 已部署（服务器先行落地，M5-A 代码
   同语义入库）；3G 报警监控留后续批次（无监控基建）。
4. 分页已落账（M5-C），无界结果超帧拒绝的历史缺口关闭。
