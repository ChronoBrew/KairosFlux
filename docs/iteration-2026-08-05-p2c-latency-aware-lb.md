# 迭代复盘：P2C + 峰值 EWMA 延迟感知负载均衡

日期：2026-08-05　范围：`service/cluster`

## 背景

网关已有有界负载一致性哈希（`BoundedRing`，管局部性 + 负载上界）。再上一个互补的高级 LB：**Power of Two Choices + 峰值 EWMA**（Finagle/Envoy 同款，源自 "The Power of Two Random Choices"），管**延迟感知**——把请求持续导向更快、更空闲的后端。

## 算法

每次**随机取两个**后端，选代价更低者：

```
score = ewmaLatency × (inflight + 1)
```

- `ewmaLatency`：该后端延迟的指数加权移动平均（历史延迟，平滑）。
- `(inflight + 1)`：当前在途数（空闲后端也有区分度）。
- 冷启动 `ewma=0 → score=0 → 优先探测`（类慢启动）。

「只比两个」而非「全局选最优」是关键：极小开销拿到接近最优的分布，同时**避免羊群效应**（全局最优会让大家一窝蜂涌向同一瞬时最优后端）。

## 验证（压测量化）

`TestP2C_RoutesAwayFromSlowBackend`：1 个慢后端（50ms）+ 3 个快后端（5ms），5000 次请求：

| | 慢后端收到 | 平均延迟 |
| --- | --- | --- |
| 纯随机（基线） | ~1250（M/4） | 16.25 ms |
| **P2C + EWMA** | **1** | **5.0 ms**（约 3.2×↓） |

P2C 几乎完全避开慢后端、把负载均分到三个快后端，平均延迟降到接近纯快后端水平。`-race` 干净、全仓 18 包全绿、零依赖不变。

## 定位与边界（诚实）

- **无状态请求/副本 LB 原语**：适合把读请求在一组副本间择优（与 `BoundedRing` 互补：一个管局部性+负载有界，一个管延迟感知）。不用于有状态数据放置（那用 `NodeFor`/`ShardOf`）。作为 `cluster` 原语提供，待接入 ShardKV 的副本读路径。
- **不主动重探已恢复的后端**：纯 EWMA 下，一个变慢后再恢复的后端 ewma 仍高、几乎不再被选中（本测试里慢后端探测一次后 score 恒高 → 只收到 1 个）。生产实现会加 EWMA 衰减/周期探测让其有机会回到轮转。本版先给核心算法。
