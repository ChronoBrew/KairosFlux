# 迭代复盘：有界负载一致性哈希——用 Google 算法消除路由热点

日期：2026-08-05　范围：`service/cluster`

## 背景

网关路由此前是 vanilla 一致性哈希（`HashRing.NodeFor`）。它对**均匀** key 分布很好，但负载**倾斜**时（少数热点 key 承载大部分请求）会把热点压到单个节点——vanilla 一致性哈希无法限制单节点负载。

本次上一个高级路由算法：**有界负载一致性哈希**（Google, *Consistent Hashing with Bounded Loads*, 2016）。

## 算法

在一致性哈希的局部性基础上，给每个节点设容量上限：

```
capacity = ⌈(1+ε) · 总负载 / 节点数⌉
```

分配 key 时从其哈希落点**顺时针找第一个未满的节点**。于是：

- 每节点负载被限制在均值的 **(1+ε) 倍**内（消除热点）；
- 仍保持一致性哈希「增删节点移动最少」的局部性；
- 鸽巢原理保证总有未满节点（容量之和 ≥ (1+ε)·总负载 ≥ 总负载）。

## 用途定位（诚实）

这是**请求/副本负载均衡**原语：带局部性偏好、但负载有界。它允许同一 key 的不同请求在主节点满载时**溢出到邻居**，故适合**无状态请求分发**（如把转发请求均衡到一组副本）；**不适合有状态数据放置**（数据放置要求 key 恒定映射到同一节点，用 `NodeFor`/`ShardOf`）。作为 `cluster` 的独立原语提供，待接入未来的副本读/请求 LB 路径。

## 验证（负载量化）

`TestBoundedRing_BoundsHotspotUnderSkew`：4 节点、10000 请求，其中 **80% 打同一热点 key**，ε=0.25：

| | 峰值负载 |
| --- | --- |
| vanilla 一致性哈希 | **8415**（84% 压在一个节点 → 热点） |
| 有界负载环 | **3125**（= 理论上界 ⌈1.25×10000/4⌉） |

峰值负载从 8415 降到 3125（**2.7× 削减**），且**精确落在理论上界**上。另测 `Release` 归还容量、同 key 溢出到多节点。`-race` 干净、全仓 18 包全绿、零依赖不变。
